01

Runtime Topology

Realmweaver is local-first: there is no application server or database. The Vite dev server is the production runtime, the AI backend is the user's own local Claude Code CLI installation, and campaign data lives entirely in the browser. The only network-facing surface — the AI proxy — is deliberately restricted to same-origin, localhost-bound requests.

AI proxy security posture

ControlMechanism
Localhost bindvite.config.ts defaults the dev server host to 127.0.0.1; REALMWEAVER_DEV_HOST opts into a wider bind explicitly.
Origin validationEvery POST to /api/ai/generate checks Origin (when present) against ALLOWED_ORIGIN_RE — localhost / 127.0.0.1 / [::1], any port — returning 403 otherwise.
No shellCLI invocation uses execFile/spawn, never a shell string; prompts over 100 KB switch to stdin to dodge ARG_MAX without a shell.
Bounded resources4 MB request cap; 120s CLI timeout; 1 MB stdout buffer (bytes beyond that are silently truncated — a known gap, roadmap item N5).
No client-side keyANTHROPIC_API_KEY is never injected into the client bundle — the future anthropic-api provider would consume it server-side only.

Layered Architecture

Four layers, with dependencies flowing one direction. The load-bearing convention — enforced by CLAUDE.md, not the compiler — is that components import only aiService.ts for AI, never the services/ai/* modules directly.

Enforced by convention, not the compiler: components call only aiService.ts for AI (one known violation: SessionLogEditor.tsx imports services/ai/audioTranscription.ts directly — roadmap item X3); state mutation goes only through campaignService methods; domain types are imported only via the types/index.ts barrel; entity icon/color/label reads only from ENTITY_TYPE_CONFIG.

Smart Linking Pipeline
